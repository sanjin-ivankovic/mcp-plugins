# Tools of the `homelab` server

Generated by `plugins/homelab/server/tools/gen_tools_doc.py`; do not edit by
hand. Every tool is annotated `readOnlyHint: true`.

## `homelab_overview`

Parameters: none

One-call health summary of every configured system (PVE, PBS, Unraid,
Technitium, Pi-hole, Komodo, Semaphore, ArgoCD). Each system is queried in
parallel with a timeout; a failing system shows its error without hiding the
others.

## `pve_nodes`

Parameters: none

Proxmox VE nodes: status, CPU/memory use, uptime, PVE version.

## `pve_guests`

Parameters: `type`, `status`, `tag`, `include_templates`, `limit`

List LXC containers and VMs with status, tags and resource use. Filter by type
(lxc|qemu), status (running|stopped) or tag.

## `pve_guest`

Parameters: `vmid`

One guest by VMID: config, live status and snapshots.

## `pve_storage`

Parameters: none

Storage pools on every node with usage percentage and content types.

## `pve_tasks`

Parameters: `errors_only`, `since_hours`, `limit`

Recent cluster tasks (vzdump, start/stop, snapshots). errors_only keeps non-OK
ones.

## `pve_backup_jobs`

Parameters: none

Scheduled vzdump backup jobs and the guests that no backup job covers.

## `pbs_datastores`

Parameters: none

PBS datastores: usage, estimated full date, last garbage collection.

## `pbs_snapshots`

Parameters: `datastore`, `backup_type`, `backup_id`, `ns`, `limit`

PBS backups. Without backup_id: one row per backup group (last backup time,
count). With backup_type (vm|ct|host) and backup_id (e.g. the VMID): that
group's snapshots with size and verify state.

## `pbs_tasks`

Parameters: `errors_only`, `since_hours`, `limit`

PBS tasks (backup, verify, prune, garbage collection, sync). errors_only by
default.

## `pbs_backup_coverage`

Parameters: `max_age_hours`

Backup coverage: every PVE guest compared with PBS backup groups. Lists guests
with no backup at all and guests whose newest backup is older than
max_age_hours.

## `unraid_system`

Parameters: none

Unraid host: OS and Unraid/API versions, CPU, uptime, current CPU and memory
use.

## `unraid_array`

Parameters: none

Unraid array: state, capacity, and per-disk status, temperature and fill level
for parity, data and cache disks.

## `unraid_docker`

Parameters: `state`, `limit`

Docker containers on Unraid with state, image and autostart. state filters,
e.g. RUNNING or EXITED.

## `unraid_vms`

Parameters: none

Virtual machines defined on Unraid and their state.

## `unraid_shares`

Parameters: none

Unraid user shares with size, used and free space.

## `unraid_notifications`

Parameters: `limit`

Unread Unraid notifications (alerts, warnings, info) with counts.

## `dns_zones`

Parameters: none

Technitium zones on every node with SOA serials, DNSSEC and sync state.
problem_zones lists zones whose serials disagree or whose secondary sync
failed.

## `dns_records`

Parameters: `zone`, `name`, `node`, `limit`

Records of a zone (or of one name inside it) as stored on a node. Comments
show ownership: 'Via ...' (DHCP) and 'Cluster managed record' are Technitium-
owned.

## `dns_dhcp_scopes`

Parameters: `node`

DHCP scopes on the DHCP node (ns1 by default) with ranges and enabled state.

## `dns_dhcp_leases`

Parameters: `scope`, `search`, `node`, `limit`

DHCP leases. search matches hostname, IP or MAC (case-insensitive substring).

## `dns_stats`

Parameters: `period`, `node`, `top`

Dashboard statistics per node: query totals, NXDOMAIN/SERVFAIL counts, top
clients and domains for the period.

## `dns_query_log`

Parameters: `node`, `domain`, `client`, `rcode`, `limit`

Query log of a node via its installed query-logger app. Filter by domain
(qname), client IP, or rcode (e.g. NxDomain, ServerFailure, Refused).

## `pihole_status`

Parameters: none

Pi-hole status per node: blocking state, versions (core/web/FTL/docker),
gravity size, list and domain counts, FTL uptime and the number of diagnosis
messages.

## `pihole_stats`

Parameters: `node`, `top`

Pi-hole statistics per node: total/blocked/forwarded/cached queries, reply
types, top queried and blocked domains, top clients and upstreams with
response times.

## `pihole_query_log`

Parameters: `node`, `domain`, `client`, `upstream`, `status`, `limit`

Pi-hole query log of one node, newest first. Filter by domain, client IP,
upstream or status (e.g. GRAVITY, REGEX, DENYLIST for blocked; FORWARDED,
CACHE).

## `pihole_lists`

Parameters: `node`, `limit`

Lists and domain entries of a node: adlists/allowlists (address, enabled,
domain count, download status, last update) and exact/regex allow and deny
entries.

## `pihole_search`

Parameters: `domain`, `partial`, `node`, `limit`

Why is a domain blocked or allowed? Searches gravity lists and allow/deny
entries on every node unless node is given. partial=true also matches
subdomains.

## `pihole_messages`

Parameters: none

Pi-hole diagnosis messages per node: list download failures, rate-limited
clients, DNSSEC or upstream problems, load and disk warnings.

## `pihole_history`

Parameters: `node`, `per_client`, `limit`

Query history of one node over the last 24 h in 10-minute slots (total,
blocked, cached, forwarded). per_client=true returns the per-client series
instead.

## `pihole_logs`

Parameters: `node`, `source`, `next_id`, `limit`

Tail of a Pi-hole log: ftl (FTL warnings), dnsmasq (per-query log) or
webserver. Pass the returned next_id to read only newer lines.

## `pihole_config`

Parameters: `node`, `modified_only`, `prefix`

Pi-hole settings of one node. By default only the keys that differ from Pi-
hole's defaults, with whether each is pinned by an FTLCONF_ variable. prefix
narrows to a section (e.g. dns, webserver.api).

## `pihole_config_diff`

Parameters: none

Settings that differ between the Pi-hole nodes (webserver.domain, which is per
node by design, is ignored). Empty differences means the pair is consistent.

## `komodo_servers`

Parameters: none

Komodo servers (Periphery agents) with connection state and version.

## `komodo_stacks`

Parameters: `only_problems`, `limit`

Komodo stacks: state, server, deployed commit vs repo HEAD (head_differs is
informational: unrelated commits move HEAD without a redeploy), services with
image updates available.

## `komodo_stack`

Parameters: `stack`

One Komodo stack: deploy info, commit messages, missing files, remote errors
and per-service container state.

## `komodo_updates`

Parameters: `failed_only`, `limit`

Recent Komodo updates (deploys, syncs, procedure runs), newest first.

## `komodo_sync_status`

Parameters: none

Komodo ResourceSync state: last sync, pending resource changes and pending
deploys that a sync would execute. Reports only, never runs the sync.

## `semaphore_tasks`

Parameters: `project`, `template`, `failed_only`, `limit`

Recent Semaphore task runs (newest first) with template, status, who ran it
and commit. failed_only keeps error/failed/stopped runs.

## `semaphore_task_output`

Parameters: `task_id`, `project`, `tail`

Output of one Semaphore task (last `tail` lines).

## `drift_report`

Parameters: `scopes`, `include_terraform`

Drift report across the homelab. Scopes: argocd (apps not Synced+Healthy),
sealedsecrets (not unsealed in-cluster), komodo (stacks down or missing files,
pending ResourceSync), kryptos (status: validate+audit+diff in argo-apps), dns
(technitium/pihole/semaphore --doctor in proxmox-infra), terraform (lxc/talos
drift-detect + unifi plan; slow, opt-in). Each check reports
clean|drift|error|skipped. Reports only: fixes go through the repo skills.

## `drift_render_check`

Parameters: `app_name`

Render an argo-apps app twice with `kustomize build --enable-helm` and diff
the output. Any difference is non-determinism that ArgoCD will show as
permanent drift.
