# Tools of the custom servers

Generated by `plugins/homelab/server/tools/gen_tools_doc.py`; do not edit by
hand. Each heading carries the tool's title. Every `homelab` and `searxng`
tool is annotated `readOnlyHint: true`. Of the `opengist`, `docmost` and
`silverbullet` tools, those that only add data are marked `(writes)` and
those that can replace or remove data `(destructive)`.

## `homelab` server

### `homelab_overview`: Homelab health overview

Parameters: none

One-call health summary of every configured system (PVE, PBS, Unraid,
Technitium, Pi-hole, Komodo, Semaphore, ArgoCD, Traefik, Alertmanager, ntfy,
Vault). Each system is queried in parallel with a timeout; a failing system
shows its error without hiding the others.

### `pve_nodes`: Proxmox nodes

Parameters: none

Proxmox VE nodes: status, CPU/memory use, uptime, PVE version.

### `pve_guests`: Proxmox guests

Parameters:

- `type`: lxc or qemu; both when absent
- `status`: Guest status, e.g. running or stopped
- `tag`: Only guests carrying this Proxmox tag
- `include_templates`: Also list templates
- `limit`: Rows to return, 1-1000

List LXC containers and VMs with status, tags and resource use. Filter by type
(lxc|qemu), status (running|stopped) or tag.

### `pve_guest`: Proxmox guest

Parameters:

- `vmid`: Guest VMID

One guest by VMID: config, live status and snapshots.

### `pve_storage`: Proxmox storage

Parameters: none

Storage pools on every node with usage percentage and content types.

### `pve_tasks`: Proxmox tasks

Parameters:

- `errors_only`: Only tasks that did not end OK
- `since_hours`: How far back to look, in hours
- `limit`: Rows to return, 1-1000

Recent cluster tasks (vzdump, start/stop, snapshots). errors_only keeps non-OK
ones.

### `pve_backup_jobs`: Proxmox backup jobs

Parameters: none

Scheduled vzdump backup jobs and the guests that no backup job covers.

### `pbs_datastores`: PBS datastores

Parameters: none

PBS datastores: usage, estimated full date, last garbage collection.

### `pbs_snapshots`: PBS backups

Parameters:

- `datastore`: Datastore name; every datastore when absent
- `backup_type`: vm, ct or host
- `backup_id`: Backup id, e.g. the VMID; lists that group's snapshots
- `ns`: Namespace; every namespace when absent, "" for the root
- `limit`: Rows to return, 1-1000

PBS backups in every namespace unless ns names one ("" is the root). Without
backup_id: one row per backup group (last backup time, count, namespace). With
backup_type (vm|ct|host) and backup_id (e.g. the VMID): that group's snapshots
with size and verify state.

### `pbs_tasks`: PBS tasks

Parameters:

- `errors_only`: Only tasks that did not end OK
- `since_hours`: How far back to look, in hours
- `limit`: Rows to return, 1-1000

PBS tasks (backup, verify, prune, garbage collection, sync). errors_only by
default.

### `pbs_backup_coverage`: Backup coverage

Parameters:

- `max_age_hours`: Hours after which a guest's newest backup counts as too old

Backup coverage: every PVE guest compared with the PBS backup groups of every
datastore and namespace. Lists guests with no backup at all and guests whose
newest backup is older than max_age_hours.

### `unraid_system`: Unraid system

Unraid host: OS and Unraid/API versions, CPU, uptime, current CPU and memory
use.

### `unraid_array`: Unraid array

Parameters: none

Unraid array: state, capacity, and per-disk status, temperature and fill level
for parity, data and cache disks.

### `unraid_docker`: Unraid containers

Parameters:

- `state`: Container state, e.g. RUNNING or EXITED
- `limit`: Rows to return, 1-1000

Docker containers on Unraid with state, image and autostart. state filters,
e.g. RUNNING or EXITED.

### `unraid_vms`: Unraid VMs

Parameters: none

Virtual machines defined on Unraid and their state.

### `unraid_shares`: Unraid shares

Parameters: none

Unraid user shares with size, used and free space.

### `unraid_notifications`: Unraid notifications

Parameters:

- `limit`: Notifications to return, 1-200

Unread Unraid notifications (alerts, warnings, info) with counts.

### `technitium_zones`: DNS zones

Parameters: none

Technitium zones on every node with SOA serials, DNSSEC and sync state.
problem_zones lists zones whose serials disagree or whose secondary sync
failed.

### `technitium_records`: DNS records

Parameters:

- `zone`: Zone name, e.g. example.test
- `name`: One name inside the zone; the whole zone when absent
- `node`: Node name from the config; the first node when absent
- `limit`: Rows to return, 1-1000

Records of a zone (or of one name inside it) as stored on a node. Comments
show ownership: 'Via ...' (DHCP) and 'Cluster managed record' are Technitium-
owned.

### `technitium_dhcp_scopes`: DHCP scopes

Parameters:

- `node`: Node name from the config; the node marked dhcp when absent

DHCP scopes on the DHCP node (the one marked dhcp) with ranges and enabled
state.

### `technitium_dhcp_leases`: DHCP leases

Parameters:

- `scope`: Scope name; every scope when absent
- `search`: Case-insensitive substring of hostname, IP or MAC
- `node`: Node name from the config; the node marked dhcp when absent
- `limit`: Rows to return, 1-1000

DHCP leases. search matches hostname, IP or MAC (case-insensitive substring).

### `technitium_stats`: DNS statistics

Parameters:

- `period`: Time window of the statistics
- `node`: Node name from the config; every node when absent
- `top`: Entries in each top list

Dashboard statistics per node: query totals, NXDOMAIN/SERVFAIL counts, top
clients and domains for the period.

### `technitium_query_log`: DNS query log

Parameters:

- `node`: Node name from the config; the first node when absent
- `domain`: Query name to match
- `client`: Client IP address
- `rcode`: Response code, e.g. NxDomain, ServerFailure or Refused
- `limit`: Entries to return, 1-500

Query log of a node via its installed query-logger app. Filter by domain
(qname), client IP, or rcode (e.g. NxDomain, ServerFailure, Refused).

### `pihole_status`: Pi-hole status

Parameters: none

Pi-hole status per node: blocking state, versions (core/web/FTL/docker),
gravity size, list and domain counts, FTL uptime and the number of diagnosis
messages.

### `pihole_stats`: Pi-hole statistics

Parameters:

- `node`: Node name from the config; every node when absent
- `top`: Entries in each top list, 1-100

Pi-hole statistics per node: total/blocked/forwarded/cached queries, reply
types, top queried and blocked domains, top clients and upstreams with
response times.

### `pihole_query_log`: Pi-hole query log

Parameters:

- `node`: Node name from the config; the first node when absent
- `domain`: Domain to match
- `client`: Client IP address
- `upstream`: Upstream server that answered
- `status`: Query status, e.g. GRAVITY, REGEX, DENYLIST, FORWARDED or CACHE
- `limit`: Entries to return, 1-500

Pi-hole query log of one node, newest first. Filter by domain, client IP,
upstream or status (e.g. GRAVITY, REGEX, DENYLIST for blocked; FORWARDED,
CACHE).

### `pihole_lists`: Pi-hole lists

Parameters:

- `node`: Node name from the config; the first node when absent
- `limit`: Rows to return, 1-1000

Lists and domain entries of a node: adlists/allowlists (address, enabled,
domain count, download status, last update) and exact/regex allow and deny
entries.

### `pihole_search`: Why a domain is blocked

Parameters:

- `domain`: Domain to look up
- `partial`: Also match subdomains
- `node`: Node name from the config; every node when absent
- `limit`: Maximum matches Pi-hole returns

Why is a domain blocked or allowed? Searches gravity lists and allow/deny
entries on every node unless node is given. partial=true also matches
subdomains.

### `pihole_messages`: Pi-hole messages

Parameters: none

Pi-hole diagnosis messages per node: list download failures, rate-limited
clients, DNSSEC or upstream problems, load and disk warnings.

### `pihole_history`: Pi-hole query history

Parameters:

- `node`: Node name from the config; the first node when absent
- `per_client`: Split each slot by client
- `limit`: Ten-minute slots to return, 1-1000

Query history of one node over the last 24 h in 10-minute slots (total,
blocked, cached, forwarded). per_client=true returns the per-client series
instead.

### `pihole_logs`: Pi-hole logs

Parameters:

- `node`: Node name from the config; the first node when absent
- `source`: ftl warnings, the dnsmasq per-query log or the webserver log
- `next_id`: next_id from the previous call, to read only newer lines
- `limit`: Rows to return, 1-1000

Tail of a Pi-hole log: ftl (FTL warnings), dnsmasq (per-query log) or
webserver. Pass the returned next_id to read only newer lines.

### `pihole_config`: Pi-hole settings

Parameters:

- `node`: Node name from the config; the first node when absent
- `modified_only`: Only settings that differ from Pi-hole's defaults
- `prefix`: Only keys in this section, e.g. dns or webserver.api

Pi-hole settings of one node. By default only the keys that differ from Pi-
hole's defaults, with whether each is pinned by an FTLCONF_ variable. prefix
narrows to a section (e.g. dns, webserver.api).

### `pihole_config_diff`: Pi-hole settings drift

Parameters: none

Settings that differ between the Pi-hole nodes (webserver.domain, which is per
node by design, is ignored). Empty differences means the pair is consistent.

### `homelab_drift_report`: Drift report

Parameters:

- `scopes`: Scopes to check; the default set when absent
- `include_terraform`: Also run the slow Terraform plans

Drift report across the homelab. Default scopes: argocd (apps not
Synced+Healthy), externalsecrets (ExternalSecrets or ClusterSecretStores not
Ready), vault (Vault paths ExternalSecrets read that are missing or deleted,
and unreferenced ones), komodo (stacks down or missing files, pending
ResourceSync), dns (technitium and pihole doctors in proxmox-infra; technitium
needs a vault login), semaphore and pbs (their doctors). Opt-in: inventory
(inventory-doctor) and terraform (lxc/talos/backup/vault drift-detect + unifi
plan; slow, needs a vault login). Each check reports
clean|drift|error|skipped. Reports only: fixes go through the repo skills.

### `homelab_drift_render_check`: Render determinism check

Parameters:

- `app_name`: argo-apps app directory name, e.g. searxng

Render an argo-apps app twice with `kustomize build --enable-helm` and diff
the output. Any difference is non-determinism that ArgoCD will show as
permanent drift.

## `opengist` server

### `opengist_create_gist`: Create gist (writes)

Parameters:

- `files`: Filename to content; the extension picks the highlighting
- `title`: Gist title
- `description`: One-line description
- `visibility`: unlisted (link only), private or public
- `expire`: How long the gist lives

Create a gist on the homelab OpenGist and return its page URL and one raw URL
per file. files maps filename to content (the extension picks the syntax
highlighting). visibility defaults to unlisted, expire to 7days.

### `opengist_get_gist`: Get gist

Parameters:

- `id`: The 32-hex gist id from its URL

One gist with its files and contents, by id (the 32-hex id in its URL).

### `opengist_list_gists`: List my gists

Parameters:

- `limit`: Gists to return, 1-100

The user's own gists (public, unlisted and private), newest first.

## `docmost` server

### `docmost_list_spaces`: List spaces

Parameters: none

The Docmost spaces the member can see, with id, slug and name.

### `docmost_browse_tree`: Browse handbook tree

Parameters:

- `page`: Page id, slug id or URL; the space root when absent
- `depth`: Levels to expand, 1-3
- `space`: Space slug; the configured space when absent

What a part of the handbook holds: the child pages of `page` (id, slug id or
URL), or the root pages of the space when `page` is absent, expanded `depth`
levels (1-3). Use it to find where a page belongs; use docmost_search_pages to
find something by what it says.

### `docmost_search_pages`: Search handbook

Parameters:

- `query`: Words to search for
- `limit`: Hits to return, 1-50
- `space`: Space slug; every space when absent
- `title_only`: Match page titles only

Full-text search over the handbook pages, ranked, each hit with a highlighted
snippet. Search every space unless `space` (a slug) narrows it. Open promising
hits with docmost_get_page instead of answering from snippets.

### `docmost_get_page`: Read handbook page

Parameters:

- `page`: Page id, slug id or URL
- `section`: Heading text or anchor; only that section
- `offset`: Character offset into the body
- `length`: Characters to return, 100-100000

One handbook page as Markdown, with its title, URL, breadcrumb path, labels,
last update and outline of headings. Name it by id, slug id or URL. For a long
page read the outline first and ask for one `section` (heading text or
anchor), or page through with `offset` and `length`.

### `docmost_recent_changes`: Recent handbook changes

Parameters:

- `limit`: Pages to return, 1-100
- `space`: Space slug; the configured space when absent

Recently updated handbook pages, newest first.

### `docmost_list_versions`: List page versions

Parameters:

- `page`: Page id, slug id or URL
- `limit`: Versions to return, 1-100

Saved versions of a page, newest first. Docmost saves a version a few minutes
after an edit settles, so a fresh change may not be listed yet.

### `docmost_get_version`: Read page version

Parameters:

- `version_id`: Version id from docmost_list_versions

One saved version of a page (id from docmost_list_versions), as plain text.

### `docmost_get_backlinks`: Page links

Parameters:

- `page`: Page id, slug id or URL
- `direction`: incoming: pages linking here; outgoing: its links
- `limit`: Pages to return, 1-100

Pages that link to this page (incoming) or that it links to (outgoing).

### `docmost_create_page`: Create handbook page (writes)

Parameters:

- `title`: Page title
- `markdown`: Page body; no title heading
- `parent`: Parent page id, slug id or URL; space root when absent
- `labels`: Labels to set
- `space`: Space slug; the configured space when absent

Create a handbook page from Markdown, under `parent` (id, slug id or URL) or
at the space root, with optional labels. The title is the page title; do not
repeat it as a heading in the Markdown. Returns the new page's id and URL.

### `docmost_update_page`: Update handbook page (destructive)

Parameters:

- `page`: Page id, slug id or URL
- `markdown`: New body content
- `operation`: replace the body, or append or prepend to it
- `title`: New page title

Change a handbook page: its Markdown body (`operation` replace, append or
prepend) and/or its title. Read the page with docmost_get_page first; for a
small fix send the whole corrected body with replace. Docmost keeps the old
body in the page history.

### `docmost_set_labels`: Set page labels (destructive)

Parameters:

- `page`: Page id, slug id or URL
- `add`: Label names to add
- `remove`: Label names to remove

Add and/or remove labels (tags) on a handbook page by name.

## `silverbullet` server

### `silverbullet_write_page`: Write scratch page (destructive)

Parameters:

- `page`: Page name: folders separated by /, no .md
- `content`: The whole page as Markdown
- `overwrite`: Replace the page if it exists; it is not kept

Write a Markdown page to the SilverBullet space and return its URL. page is
the page name (folders with /, no .md needed). Refuses to replace an existing
page unless overwrite is true.

### `silverbullet_append_page`: Append to scratch page (writes)

Parameters:

- `page`: Page name: folders separated by /, no .md
- `content`: Markdown to add at the end

Append Markdown to the end of a SilverBullet page (created if missing) and
return its URL. The write is conditional on the page not having changed since
it was read.

### `silverbullet_read_page`: Read scratch page

Parameters:

- `page`: Page name: folders separated by /, no .md

One SilverBullet page as Markdown, by page name.

### `silverbullet_list_pages`: List scratch pages

Parameters:

- `limit`: Pages to return, 1-500

Pages in the SilverBullet space, most recently modified first.

## `searxng` server

### `searxng_search`: Web search

Parameters:

- `query`: Search terms; never internal names or IPs
- `categories`: SearXNG categories, e.g. general, it, news, science, repos
- `engines`: Engine names to use instead of the defaults
- `language`: Language code, e.g. en or de
- `time_range`: Only recent results
- `page`: Result page, from 1
- `safesearch`: 0 off, 1 moderate, 2 strict
- `limit`: Results to return, 1-50

Web search through the homelab SearXNG. Returns ranked results (url, title,
snippet, engines, score, published date) plus any direct answers, infoboxes,
suggestions and engines that did not answer. Open promising results with
searxng_fetch instead of answering from snippets.

### `searxng_fetch`: Fetch web page

Parameters:

- `url`: http or https URL
- `max_length`: Characters to return, 100-50000
- `start_index`: Character offset to start at
- `raw`: Return HTML unconverted

A web page as Markdown (headings, links and tables kept; navigation and ads
dropped), read in chunks: max_length characters from start_index, and
next_index when more remains. raw=true returns the body unconverted. Text,
JSON and XML come back as they are; binary types are refused.

### `searxng_instance`: SearXNG engines

Parameters:

- `enabled_only`: Leave out disabled engines

The SearXNG instance: version, categories, enabled engines (with the
categories they serve) and whether the limiter is on. Use it to pick
categories or engines for searxng_search.
